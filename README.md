# Log Sentinel - A Small Defensive Security Tool

Log Sentinel analyzes **SSH authentication logs** and **web server access logs** to detect
common attack behaviour and produces a prioritized report that a defender can act on.
It is strictly *defensive*: it only reads logs, never contacts hosts, and only *recommends*
a blocklist (it does not change firewall rules).

## Features / Detection Rules

| Rule | Severity | MITRE ATT&CK | What it detects |
|---|---|---|---|
| `SSH_BRUTE_FORCE` | medium / high (>=30) | T1110.001 | >=10 failed logins from one IP in 300 s |
| `SSH_PASSWORD_SPRAY` | high | T1110.003 | >=5 distinct usernames from one IP in 600 s |
| `SSH_SUCCESS_AFTER_FAILURES` | critical | T1078 | Successful login after >=5 recent failures from same IP (possible compromise) |
| `WEB_SQL_INJECTION` | high | T1190 | UNION SELECT, `' OR '1'='1`, sleep(), DROP TABLE, etc. (URL-decoded twice) |
| `WEB_XSS` | medium | T1189 | `<script`, `javascript:`, `onerror=` ... |
| `WEB_PATH_TRAVERSAL` | high | T1190 | `../`, `/etc/passwd`, encoded variants |
| `WEB_COMMAND_INJECTION` | high | T1190 | `; cat`, `| whoami`, backticks, `$(`... |
| `WEB_SCANNER_USER_AGENT` | medium | T1595 | sqlmap, nikto, nmap, gobuster, hydra ... |
| `WEB_404_ENUMERATION` | medium | T1595.003 | >=20 HTTP 404s from one IP in 60 s |

All thresholds are function parameters in `log_sentinel/detectors.py`.

## Usage

```bash
# Run on the included sample data
python3 -m log_sentinel --auth samples/auth.log --access samples/access.log --year 2026 \
        --json results/detection_results.json \
        --markdown results/detection_report.md \
        --blocklist results/recommended_blocklist.txt

# On a real server (example paths)
python3 -m log_sentinel --auth /var/log/auth.log --access /var/log/nginx/access.log
```

Exit code is `1` if any high/critical finding exists (useful for cron/CI alerting), else `0`.

## Detection Results (sample data)

The sample dataset (57 auth events, 53 web requests) contains 7 planted attack scenarios (9 distinct behaviours) plus
benign traffic including look-alikes (e.g. `q=credit+union+news`, a single password typo).

| Scenario | Source IP | Detected as |
|---|---|---|
| Account compromise (8 fails then success) | 192.0.2.44 | CRITICAL `SSH_SUCCESS_AFTER_FAILURES` |
| SSH brute force (30 fails / ~2 min) | 198.51.100.7 | HIGH `SSH_BRUTE_FORCE` |
| Password spray (12 usernames) | 203.0.113.50 | HIGH `SSH_PASSWORD_SPRAY` (+ MEDIUM brute force, since it also exceeded the failure count) |
| SQL injection with sqlmap | 198.51.100.77 | HIGH `WEB_SQL_INJECTION`, MEDIUM `WEB_SCANNER_USER_AGENT` |
| XSS + path traversal | 203.0.113.99 | MEDIUM `WEB_XSS`, HIGH `WEB_PATH_TRAVERSAL` |
| Command injection | 192.0.2.150 | HIGH `WEB_COMMAND_INJECTION` |
| Directory enumeration (40 x 404) | 192.0.2.200 | MEDIUM `WEB_404_ENUMERATION` |

**Totals:** 10 findings (1 critical, 5 high, 4 medium), detection of
**all 9 planted behaviours**, and **0 false positives** on the benign 10.0.0.x traffic.
Full output: `results/detection_results.json`, `results/detection_report.md`,
`results/detection_console.txt`.

## Limitations

See `docs/DESIGN.md` - notably: signature-based web rules can be evaded by obfuscation, and
per-IP logic does not catch distributed (botnet) attacks. Use as one layer of defense.

## Ethics / Scope

Built for defenders analysing logs they own or are authorized to analyse. Sample data is
synthetic and uses reserved documentation IP ranges (RFC 5737).
